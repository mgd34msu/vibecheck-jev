# vibecheck-jev 1.0.0

vibecheck-jev 1.0.0 is the first release: a work ledger for Claude Code and Codex agents whose reports are checked by a Jev-compatible judgment model. It builds on the vibecheck ledger and opens an existing vibecheck database unchanged.

## What it does

- **The ledger records the standard.** Nine MCP tools record the plan, claims, progress, blockers, handoffs and commits. Tasks can carry a goal, acceptance criteria, rules, accepted exceptions and a parent; the plan can carry a project policy with rules, authorizations and accepted reasons for stopping.
- **Checks read what agents report.** A done report is read against its task's goal and criteria, with the recorded commits checked against the claimed paths and data-only exceptions checked for logic. A report that claims done while showing work left keeps the task open with the reason. Blockers, releases, handoffs, claims and plan changes are read too.
- **Status shows what is verified.** `project_status` leads with an attention list and shows each task as reported and as verified. `work_history` returns every verdict with its check, version, source, model and readings.
- **Hooks check the agent's own turns.** In Claude Code and Codex, a brief to a subagent is read against the plan and the project's rules, a shell delete through an unguarded variable is refused, and a stopping reply is read for deferred work, unanswered questions, needless permission requests, overclaimed completion and facts the turn's tool output does not show.
- **Any Jev-compatible source.** The hosted TypeSafe service, open Jev-compatible servers, Laya served locally and the optional Jev-Style adapter can be configured in order, with failover, input limits, per-check routing and per-check and per-source thresholds.
- **Calibration tools.** `measure fixtures`, `measure live`, `measure replay`, `label`, `check`, `watch-agents`, `exception-check`, `report-of` and `sources` run from the same bundle.

## Compatibility

The nine tools keep their request shapes; every new field is optional and every new response field is additive. The SQLite schema version stays 1: goals, criteria, policy, verdicts, labels and reports live in new tables, so earlier vibecheck releases can still open the database. History is now immutable in the database itself, and idempotency receipts older than 30 days are pruned on write.

## Requirements

Bun 1.3.14 or later, or Node.js 24 or later, and Bash. A judgment source: set `TYPESAFE_API_KEY` for the hosted service, or configure an open source in `config.jsonc`. Without a usable source, the ledger records work as reported and the hooks let work go ahead.

## Artifacts

`bun run build:release` writes `vibecheck-jev-codex-plugin-1.0.0.zip`, `vibecheck-jev-claude-plugin-1.0.0.zip`, `vibecheck-jev-runtime-1.0.0.tar.gz` and `SHA256SUMS` to `artifacts/`. `bun run verify:release` checks the archives and runs their MCP servers and hooks on Bun and Node.js.
